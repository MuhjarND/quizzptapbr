# Cerdas Bersama PTA Papua Barat interaction contract

Source: supplied product brief. Ownership: Laravel policies and GameService enforce permissions and transitions; Blade layout supplies navigation, status/error banners, and one shared native dialog; app.css supplies all visual tokens and states. app.js owns confirmation/loading behavior; editor.js owns dynamic question fields; game.js owns polling/rendering. Native controls own selects, file inputs, radio groups, and dates (read-only display). No table selection or custom date picker.

- Forms: visible labels, server validation with an accessible error summary, required feedback, retained input. Editor uses a shared question template, stable keys, numbered order, move up/down, 2–4 choices and one correct radio. Successful saves return to quiz list with status feedback. Draft still requires valid questions; it is a completed unpublished quiz, not autosave.
- CRUD: list search/status retained in URL, pagination, empty/no-results states. Duplicate creates draft. Delete uses native accessible app-owned dialog naming quiz and consequence; saved game snapshots survive. Cancel/Escape restore focus.
- Gameplay: host-only controls, lobby joins only, server deadlines/scores, one answer, tokens stored in server session behind encrypted HttpOnly cookie. Refresh recovers identity in same browser. Status lobby → question_active → question_result → podium → finished. Host start/next/reveal request contains expected version. Early finish confirms, preserves submitted answers and opens the same staged podium; unanswered questions add zero. Zero/one participant can finish directly.
- Feedback: shared polite status banner and assertive error summary. Async controls visibly busy; failures retain data and offer retry. Polling sequential every 1.5s, pauses while hidden/offline, backs off to 5s on failure, stops on finished/pagehide. Timer uses server clock offset. No answer keys during active state.
- Tables: server pagination on history, bounded participant/session size by practical MVP use. Results expose per-participant answers and totals to owning host. Guests see nickname/score only. Leaderboard order score descending, correct count descending, correct-answer elapsed sum ascending, participant ID ascending.
- Locale: Indonesian content, id-ID numbers, Asia/Jayapura dates. Keyboard focus, semantic links/buttons, labelled fields, live status, reduced motion, touch target >=44px. Native dialog provides focus trap and inert background.

- Character selection: config/characters.php owns the six allowed stable keys; Characters presenter owns browser asset URLs and legacy fallback. JoinRequest + GameService validate keys. Native radio group in join form supports keyboard arrows, selected check/focus and preview announcement. Choices are not exclusive between players. Invalid PIN/name retains the selected character. Participant.character stores choice for the whole session and survives refresh; existing/older participants default to nala. Shared Blade character partial and game renderer use the same catalog for lobby, participant identity, leaderboard, podium and saved results.
- Sound: public/js/sound.js owns the shared Web Audio context and short cues. Controls live in a shared Blade partial on join/game. No sound before an explicit gesture unlocks browser audio; UI honestly shows Aktifkan suara until ready. Enabled preference and volume persist locally, with graceful behavior if storage/audio is unavailable. Muting effects stops current effect voices. Hidden tabs suppress sounds; refresh does not replay past transitions. Polling emits one cue per observed state change; countdown ticks once per remaining second from five to one. No voice recordings or key/score revealed before server result.
- Music: public/js/music.js shares the context, with its own buffer source, gain, mute, local preference and slider. Local original WAV loads after user interaction; controls distinguish Aktifkan musik, Memuat musik, Musik siap, Musik aktif, Musik mati, and retry. Only question_active plays; question_result pauses at the current position, next question resumes, finished stops/resets, hidden/pagehide/deadline stop. Polling cannot stack sources. Failed loading never blocks answers; an explicit retry is available. Effects briefly duck music. Existing effect preference and legacy session cookie remain stable after rebranding.
- Brand: config('app.name') is Cerdas Bersama PTA Papua Barat. Shared brand partial supplies the book symbol and two-line wordmark on every shell. host:create creates an additional host with a generated password stored as a hash and rejects an existing email. The administrator uses the same host permissions and ownership rules as other accounts.

- Per-question results: question_result renders a dedicated Peringkat sementara screen on host and participants, replacing the question/options, except for the final question. It appears only after all participants answered or the server deadline expired. Correct-answer reference and each participant's round gain remain visible on intermediate screens; active/locked-answer screens never disclose earned points or answer keys.
- Standings projection: GameService recomputes current and prior standings using the same score/correct/time/join-order tie rules. Rows expose score, previous_score, earned_score, rank, previous_rank and rank_change only with the result/finished leaderboard. Previous baseline excludes the current snapshot question. Refresh reconstructs the same standings without trusting browser history.
- Standings motion: standings.js owns numeric count-up, old-to-new row slots, cancellation, rank cues and reduced-motion behavior; standings.css owns shared geometry. Movement/coin sounds play once on a newly observed result transition, obey existing mute/volume, and do not repeat during polling or refresh. Advancing, hiding or leaving the page finishes/cancels pending animation and sound callbacks. Host may advance immediately. Final podium remains a separate finished screen.
- Final reveal: last question_result sets final_pending and withholds leaderboard, score, correctness, correct_index and distribution for host and guests, including refresh. Lihat hasil podium starts a persisted podium_step with podium_step_at. First click reveals rank min(3, participants), then Juara selanjutnya reveals the next rank. One participant reveals only rank 1; two reveal 2 then 1. API includes only winners already authorized by the host. Full final standings and detail links appear after rank 1. Results route redirects to host during podium. Legacy finished sessions remain readable without replaying a ceremony.
- Podium synchronization: GameService locks the session, validates version and a server ready_at (3.8 seconds for opening; 2.2 seconds for later steps). Double clicks, stale requests, guest controls and attempts to skip ceremony are rejected. Polling continues through podium and stops on finished. podium.js owns finite opening/rise/champion motion and cues; it offsets timing using the server clock, cancels timers when hidden/navigation/step changes, and never replays past steps on initial load. Buttons remain disabled through the reveal, preserve retry after a failed request, and support keyboard activation. Muting effects and reduced motion use existing preferences.
- Podium recovery: readiness is rechecked after clock-offset corrections and while a host request is pending. A poll that observes a committed host transition before its POST returns renders that version only once. Keyboard host actions focus the updated podium heading; refresh/hidden-tab recovery shows the currently authorized stage without replay.
